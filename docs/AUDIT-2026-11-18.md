# Failure audit: every feature, how it fails, and who sees it (2026-11-18)

The owner asked for "perfect error handling and reporting so we can have an end to end fully completed and observed and
monitored app". This is the audit (ticket 0293). It lists each capability of the iPhone app and the web equivalents that
share its backend. For each one it gives how the capability can fail, what happens today, and how severe that is. The
fixes in the same PR are marked **fixed (0293)**. Everything else has a reason for staying as it is.

Severity: **Critical** = a crash, lost progress or an unusable app on a normal path. **High** = a silent failure on a core
path, or a failure nobody can see. **Medium** = a degraded path with no message or report, or a crash only under rare
pressure. **Low** = cosmetic, or already handled well enough.

## Method

- I read every file in `ios/ColdGas/**` and `ios/Packages/ColdGasCore/Sources/ColdGasClient/**` that touches the
  network, disk, Metal, audio, haptics or the app's lifecycle, plus `src/obs/**`, `src/worker/obs.js` (read only, frozen),
  `index.html` and `src/insights.js`.
- Patterns grepped in `ios/`: `try!` (4, all on constant regex patterns), `fatalError` (0), `as!` (1, a `layerClass` cast),
  force unwraps on external data (none outside `Debug/`. `make rules` already forbids them in views), `try?` (≈150),
  each one classified below where it matters, and `print(` used as the only record of a failure (9 sites).
- On the web: `window.onerror` / `unhandledrejection` coverage, empty `catch {}` blocks (deliberate, all in
  never-throw paths: storage, beacons, analytics), fetch deadlines (src/net.js: every call has one).

## What existed before this audit

- **Web:** mature. `src/obs/` captures errors, rejections, failed lazy chunks, lost WebGL contexts, shader failures,
  physics traps and frame times. It heals what it can (breakers, a context restore, reload-once) and beacons
  signatures to `POST /coldgas/api/obs`. `GET /coldgas/api/obs/digest` flags new and regressed signatures, and
  `npm run heal` files them as tickets.
- **iPhone:** no error reporting at all. Failures were `print()`, which on a device goes nowhere. There was no
  `os.Logger` and no MetricKit. The only crash reports were Xcode Organizer's, for TestFlight testers who share
  diagnostics. Usage events (0246) go to Box Office, but they carry funnel counts, not faults.

## Findings: the backend (frozen: `src/worker/`, `wrangler.jsonc`)

| # | What | Why it matters | Sev | Proposal (owner's decision) |
|---|---|---|---|---|
| B1 | `/obs` has no platform dimension | The iPhone's reports can use `/obs` as it is (the shape fits: `build` `ios-<version>-<build>`, `dc` `phone-hi`, `tier` `high`). But a batch with `first: true` counts a session, and the digest picks the newest build by session as `current`, so an iOS build would become "current" and **web regression detection (`npm run heal`) would compare the wrong builds**. The app therefore sends `first: false`: its signatures show in the digest's `top` with their builds, and there's no per-session rate | Medium | Accept `platform: 'web' \| 'ios'` in `cleanObs`, store it in `obs_err`/`obs_evt`, and run `builds`/`regressions` per platform in the digest (`digest.platforms.ios.regressions`). | B2 | Exemplar stacks only for regressions | `top` rows carry the top frame only; the app's crash stacks (up to 6 frames, binary offsets) are stored in `obs_ex` but not surfaced for non-regressions | Low | Add `?stacks=1` to the digest to return `obs_ex.st` for the top 20 keys |
| B3 | Rate limit 30 beacons/h per IP | The web and the app on one network share it | Low | Fine at today's volume; the app flushes at most once a minute and only when it has something |

## The reporting this PR adds

### iPhone: `Report` (ios/ColdGas/App/Report.swift) and `Obs` (ColdGasClient/Obs.swift)

- **One call per failure site:** `Report.error(.render, .shader, "pipeline cg_plume failed")`. It goes to `os.Logger`
  (subsystem `com.mutaafaziz.coldgas`, one category per module: app, render, shader, physics, audio, world, net, drive,
  frame, page). That makes it readable in Console.app and in a sysdiagnose with no network. The first occurrence logs at
  `.error` and the repeats are counted, not logged. It also goes to the health queue.
- **The queue** (pure, unit-tested): signatures as the web makes them, `sig = hash12(msg|frame|build)`,
  `key = hash12(msg|frame)`, using the same FNV-1a over UTF-16 as `src/obs/signature.js`, with the same message
  normalisation and secret redaction. It's deduped with counts, capped at 32 signatures, and persisted in UserDefaults
  (`coldgas.obs.v1`) so a fault survives a crash or a missing network. A batch is removed only once `/obs` has answered 2xx.
- **MetricKit** (`MXMetricManager`): crash, hang, CPU-exception, disk-write-exception and slow-launch diagnostics, plus
  the daily payload's foreground exit counts (memory limit, watchdog, bad access, abnormal…). They're mapped to `/obs`
  entries in pure code (`Obs.fromDiagnostics(json:)`, tested on Apple's JSON shape). Only the exception type and signal
  names, the termination reason's kind (watchdog, jetsam), hang/launch durations folded to a bucket, and up to six frames
  of the attributed thread as `0x<offset>@<binary>` leave the device. A diagnostic's own `appVersion`/`appBuildVersion`
  becomes its build, so a crash in 1.2.0 delivered after an update to 1.2.1 is filed under 1.2.0.
- **Sending:** `POST https://mutaafaziz.com/coldgas/api/obs` (the existing endpoint, unchanged), ≤ 8 kB, at most once a
  minute, only on the title, the results or going to the background (never in a countdown, a run or a replay). It uses
  `Net.session` (ephemeral, no cookies). It's gated like the usage events: off under a test or tool flag, and off when
  Settings → Privacy → Share usage stats is off (that switch now says "and crash reports"). DEBUG `-obs-dry` prints
  each batch instead of sending it.

**What leaves the phone (for App Store Connect's App Privacy):** Diagnostics → **Crash Data** (exception and signal
names, up to six binary offsets of the crashing thread), **Performance Data** (hang and launch-time buckets, CPU and disk
exceptions, daily exit counts by reason) and **Other Diagnostic Data** (an error signature: a normalised message such as
"pipeline cg_plume failed", the Swift function and file name where it was reported, and a count). Also sent: the app's
version and build, the constant device class `phone-hi` and the tier `high`. **Not linked** to the user: no install id, no
device id or model, no OS version, no locale and no IP stored (the Worker keeps only a daily salted hash for the rate
limit). **Not tracking.** Purpose: **App Functionality**. Those three rows are in `ios/store/app-privacy.md` and in
`PrivacyInfo.xcprivacy`.

**The new features in open PRs** (#420, #429, #434, #435), read but not yet on main. These go in when each lands:
- **#429 brake bias:** `FreeDrive.brakeBias` is read from UserDefaults with no range or NaN check, and a value over 1
  gives negative rear brake torque. Guard it with `Guard.number(_, in: 0.3...0.8, fallback: DriveSpec.brakeBias)`.
- **#429 `RunSkids` / `SkidMarks.mark`:** guard the time index (`Int(t * hz)`) and keep a non-finite quad out of the ring.
  The ring itself is bounded.
- **#429:** reset the drive's slip memory (`betaPrev`, `hbHold`) when the car resets, and clear the handbrake in `endDrive`.
- **#420 roam challenges:** decode the saved challenges entry by entry, so one bad field doesn't erase the rest. Refuse a

  car reset.
- **#434 + #435:** they merge onto the same lines in Renderer (`depthRes`). Keep `look.readsDepth || nGlows > 0`, or 8-bit

- **#435:** guard the hero box against an empty roadster mesh, and `carM.inverse` against a degenerate matrix.

## How the owner sees it

- **`npm run obs:report`** (`scripts/obs-report.mjs`) prints production's digest in one screen. It splits the web build
  from the iPhone builds (`ios-*`), shows the top signatures for each with their counts and frames, lists the flagged
  regressions and the last three days of the players' funnel. `--json` gives the same for a tool, and `--digest=<url|file>`
  points it elsewhere.
- **Alert thresholds** (its exit code, for a cron or an agent):
  - exit **2**: any **P0 regression** in the digest (the Worker's rule: a fatal kind (`trap`, `ctxlost`, `frame`,
    `unclean`), the `physics`/`webgl` module, or ≥ 10 % of sessions), **or** an iPhone build with **≥ 3 crashes**
    (`unclean`) or **≥ 5 hangs** (`frame`) in the window, **or** any iPhone `render`/`shader` failure (a black stage).
  - exit **1**: a P1 regression, or any new iPhone signature.
  - exit **0**: quiet.
- **Symbolicating an iPhone crash frame** `0x1a2b3c@ColdGas`: with that build's dSYM (from the archive,
  `build/archive/ColdGas.xcarchive/dSYMs`), run
  `atos -arch arm64 -o ColdGas.app.dSYM/Contents/Resources/DWARF/ColdGas -l 0x100000000 0x10001a2b3c` (the offset added
  to the text segment's load address).
- **On a device in hand:** Console.app → the phone → filter `subsystem:com.mutaafaziz.coldgas`.
- **Already there:** the web's For nerds → Health panel, `npm run heal` (tickets from regressions), Xcode Organizer
  (TestFlight crashes).

## Not changed, on purpose

- `src/worker/`, `wrangler.jsonc`, `.github/workflows/`, `agents/control.json` are frozen. B1–B3 are proposals.
- No gameplay, sim or scorer change: `npm test` and `make test` (52 run vectors) pass bit-exact.
- A POST to `/scores` still isn't retried past a 503 (N7).
